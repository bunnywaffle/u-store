# U Store

A fast, native software store that works across **every Linux distribution** — Flatpak
first, your distro's own packages where they exist, Snap when present — built with
[MyGo](https://mygo.run) and Go. One ~11 MB binary, no runtime dependencies beyond GTK 3
and WebKitGTK on Linux.

## What it does

- **Discover** — featured picks (curated) + live trending apps streamed from Flathub.
- **Browse** — categories; selecting one runs a live Flathub search by category.
- **Search** — debounced, live Flathub search; falls back to the embedded catalog offline.
- **Installed** — one list merged from every backend on the machine (Flatpak user +
  system, native, Snap), with Open and two-click-confirm Remove.
- **Updates** — pending updates from every backend, applied transactionally (native
  managers only support whole-transaction upgrades, so "Update all" is all-or-nothing
  per manager), capped at 100 rendered rows for gigantic distro upgrades.
- **Install file** — dropped or picked package files (.deb, .rpm, Arch .pkg.tar.*,
  Alpine .apk, .snap, .flatpak bundles, .AppImage) are inspected for the running
  distro; U Store shows exactly what it will run (with the full command),
  refuses mismatched formats, and installs through the native manager (or integrates
  AppImages into ~/Applications + the app menu).
- **Settings** — auto-detected distro, backend table (ready/missing), Flathub remote
  setup, "prefer native packages" preference, about panel.

## Architecture

```
main.go                  wires the Store service into a MyGo window (hidden title bar)
internal/store/
  types.go               JSON contract with the frontend (AppSummary, UpdateInfo, …)
  catalog.json           the curated catalog — edit this to add apps
  catalog.go             embedded catalog loader + local search fallback
  detect.go              /etc/os-release parsing → apt | dnf | pacman | zypper | apk
  flathub.go             Flathub API client (search, appstream) with timeouts
  backends.go            Source interface + implementations (flatpak, dnf, apt,
                         pacman, zypper, apk, snap) — one small type each
  local.go               local package install: detect format, read metadata
                         (dpkg-deb / rpm -qp / filename parsing), plan the
                         right command for THIS distro, install it
  service.go             the Store service bound to the frontend; caching, enrichment,
                         orchestrates install/remove/update/launch
src/
  main.ts                shell: routing (with a nav stack), search focus, badge, boot
  api.ts                 every Go call, wrapped for graceful offline degradation
  components.ts          cards, skeletons, toasts, empty states, icon fallback
  actions.ts             install/remove flows driving buttons, progress bars, consoles
  icons.ts               inline SVG icon set (no icon font, no emoji)
  views/*.ts             one module per view (discover, browse, search, detail,
                         installed, updates, settings)
  style.css              the whole design system (light/dark via prefers-color-scheme)
```

### Data flow

1. Frontend calls `Store.*` (typed client in `src/mygo.ts`, generated by `mygo generate`).
2. `service.go` answers by combining: embedded catalog, live Flathub API, and local
   package-manager queries — whichever apply, each with a timeout.
3. Operations stream progress back through a `*mygo.Channel[InstallEvent]`, rendered as
   a determinate/indeterminate progress bar, a status line, and an optional console.

### Adding a package manager

1. Implement the `Source` interface in `internal/store/backends.go` (copy `aptSource`,
   they're all ~60 lines).
2. Add a case to `familyOf` in `detect.go` if the distro ID is new.
3. Register it in `detectSources` and add its `BackendInfo` to `infos()` and
   `nativeInfoFor`.
4. Add the ref parser/claim in `service.go` (`nativeBackendIDs`) if it holds real
   database state — then `installed`, `updates`, and installed-state merge work for free.

### Adding an app to the store

Append an entry to `internal/store/catalog.json`. Only `id` (the Flathub app ID) and
`name` are required; `native` maps the package name per manager (leave `{}` to offer
Flatpak only). Icons come from Flathub automatically.

## Development

```sh
npm install
npm run dev          # mygo dev: live reload + dev inspector
npm run build        # produces build/linux-amd64/: binary, .deb, .rpm, PKGBUILD, tarball
npm run typecheck    # tsc --noEmit
go test ./...        # backend unit tests
go tool mygo doctor  # check the machine has what MyGo needs
```

Notes:

- `go.mod` pins the MyGo CLI as a Go tool; `mygo` itself runs via `npx`/`go run`.
- Linux needs GTK 3 and WebKitGTK 4.1 (`webkit2gtk-4.1` / `libwebkit2gtk-4.1-0`).
- Native installs/removals go through `pkexec` when not root — no custom password
  handling, standard polkit auth like every other Linux store.
- The UI works in a plain browser too (all backend calls fail gracefully and it shows
  the offline states), which is handy for styling work.
